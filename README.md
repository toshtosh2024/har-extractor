# HAR 抽出ツール

`index.html` をブラウザーで開くだけで使えます（`file://` 対応）。インストール、ビルド、サーバー、外部ライブラリは不要です。読み込んだHARはブラウザー内だけで処理し、外部へ送信しません。

1. Chrome DevTools の「Network（ネットワーク）」を開き、必要な通信を記録します。ページ遷移を含める場合は「Preserve log」を有効にします。
2. 通信一覧を右クリックし「Save all as HAR with content」、またはツールバーのHARエクスポートを選択して保存します。表記はChromeのバージョンにより異なります。レスポンス本文が含まれるHARを使用してください。
3. 本ツールの「HARファイルを選択」、またはドラッグ＆ドロップで読み込みます。
4. 必要な通信を選択し「選択をZIPでダウンロード」を押します。行の「⬇」から個別保存もできます。

URL検索、カテゴリ、本体ありのみ表示で一覧を絞り込めます。形式のチェックボックスは、表示フィルターに関係なく同じ形式の全通信を選択します。フィルターを変えても選択は保持されます。「選択解除」は全選択を解除します。

行のチェックボックスをShift+クリックすると、直前にクリックした行から現在の表示順で範囲選択・解除できます。本体のない行は対象外です。フィルター・並び順の変更やHARの再読み込みで、範囲の起点はリセットされます。

並び順メニューまたは列見出しでソートできます。ZIP内のレスポンスと `manifest.csv` は、選択した通信を現在のソート順で出力します。フォルダー構造保持、リクエスト本文の追加出力にも対応しています。リクエスト本文は `_requests/` に通信順の0始まり番号付きで保存します。同名ファイルには連番を付けます。

`data:` URLは `data_番号.ext`、`blob:` URLは `blob_番号.ext` として保存します。番号は通信順の0始まりです。フォルダー構造保持時は、それぞれ `_data/`・`_blob/` に入ります。拡張子はdata URL内のMIME（省略・不正時はレスポンスMIME）、blob URLではレスポンスMIMEから決定します。Windowsの予約名には `_` を付けます。

行をクリックするとヘッダー、クエリ、リクエスト本文、レスポンスプレビューを表示します。HTMLなどは文字列として表示し、実行しません。テキストプレビューは先頭200 KBまでです。SVGは画像とソースの両方を表示します。本体のない通信は一覧に表示しますが、抽出対象にはできません。

ZIPは無圧縮・UTF-8ファイル名です。ZIP64には対応せず、4 GBまたは65535ファイルを超える場合はエラーを表示します。実際に扱えるサイズはブラウザーのメモリーにも依存します。

## 画像をPDFに結合

「画像をPDFに結合（画面の並び順）」をオンにすると、選択した `image/*` の通信を現在のソート順でPDFにまとめます。フィルターで非表示になっている選択済み画像も対象です。画像だけを選択し、元画像を残さず、追加するリクエスト本文もなければ `<HAR名>_images.pdf` を直接保存します。それ以外はPDFをZIPのルートに追加します。

「元の画像もZIPに含める」はPDF結合時だけ有効です。オフなら画像ファイルをPDFに置き換え、オンなら元画像も残します。ZIPの `manifest.csv` には各画像の `PDF名#page=N` を記録し、元画像も残す場合はその行も記録します。両オプションはHARの読み込み時にオフに戻ります。

1画像1ページ、余白なし、96 dpi換算です。EXIFの表示方向を反映し、ページの長辺は最大14,400pt、変換する画像の長辺は最大8,000pxに制限します。SVGに固有サイズがない場合は幅1,024pxを基準に縦横比を補い、比率も不明なら正方形にします。透過部分は白、アニメーション画像は先頭フレームになります。通常のグレー／RGB JPEGは元データを埋め込み、それ以外はRGB画素を可逆圧縮するため、PDFが大きくなる場合があります。

画像が選択されていなければ通常のZIPを保存して案内を表示します。読み込めない画像はスキップして名前を表示します。全画像が失敗した場合はPDFを作らず、残るファイル（保持する元画像やリクエスト本文を含む）があればZIPを作成します。画像形式の対応範囲はブラウザーに依存します。`CompressionStream` 非対応時は案内を表示してPDFを省略し、元画像を含む通常のZIPに戻します。

## サンプルとテスト

Node.js 22以降で、作業フォルダーから実行します。npm依存関係はありません。

```sh
node tests/make-sample-har.mjs
node --test tests/core.test.mjs
```

17通信を含む `tests/sample.har` を生成します。既存の0～13番は維持し、14番に120×80の半透明PNG、15番に120×80の実JPEG、16番にサイズ指定付きSVGを追加しています（画面の通信番号は15～17）。9番の簡易JPEGは画像読込失敗の確認にも使えます。JPEGは定数として埋め込まれているため、生成時に画像変換ツールは不要です。

テストはコアをHTMLから取り出してNodeのVMで実行し、日本語、名前の安全性、ソート、CRC32、CSV、ZIP、JPEG解析・EXIF、PDFのxref・ストリーム長・ページサイズを検証します。`unzip` があれば `unzip -t` でも検証します。サンプルがない場合はコアテストが自動生成します。

5,000件のHARをメモリー上で生成するテストも含みます。全ソートキー、フォルダー保持あり・なしでの重複名解消、500ファイルのZIP内容を検証します（実行時間の制限は設けていません）。

PDF／ZIPの振り分け・失敗時の処理・マニフェスト・RGB圧縮のUIテストも実行できます。DOMと画像デコーダーの代替を使うため、実ブラウザーでの画像表示確認とは別です。

```sh
node --test tests/pdf-ui.test.mjs
```

macOSでSwiftが使える場合、保存したPDFをPDFKitで開いてページ数とサイズを確認できます。この検証はNodeのテストからは実行しません。末尾にフォルダーを指定すると、目視確認用のページPNGも出力します。

```sh
swift tests/verify-pdf.swift sample_images.pdf
swift tests/verify-pdf.swift sample_images.pdf /tmp/har-pdf-preview
```
